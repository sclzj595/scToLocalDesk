# Doc02 产品需求文档 PRD V2.0

> 版本：V2.0（2026-10-21 优化：新增 5.6 无人值守模式需求、5.7 设置页需求，更新安全需求与风险清单）

## 1. 产品简介

SC 邻桌 scToLocalDesk，企业内网远程协助工具，替代向日葵、ToDesk 内网场景；别名代替 IP 寻址，连接默认需要被控同意，绿色单 EXE。

## 2. 角色定义

- 被控用户（员工）：设置本机别名、接收协助弹窗、同意 / 拒绝连接、会话内一键断开、收发文件；可选开启无人值守模式并设置访问密码
- 控制用户（IT）：输入别名发起协助、远程操控、文件上传下载、查看在线设备列表、按需调整画质与发现参数

## 3. 术语表

- DeviceAlias：设备别名，内网唯一字符串，2~20 字符，中文 / 字母 / 数字，作为寻址标识
- Discovery：设备发现服务，UDP 组播心跳，上报别名、IP、端口
- Transport：传输层，抽象接口；V1 默认实现 QWebSocket，可替换 RawTcp
- Session：远程会话，多路复用画面帧、键鼠信令、文件分片、会话控制指令
- EventBus：事件总线，模块解耦，Core 内部通信机制
- PlatformAdapter：平台适配层，收敛 Qt/Windows 原生 API 依赖，Core 无 Qt
- Unattended（无人值守模式）：被控端显式开启的自动同意机制，凭独立访问密码鉴权，全程审计，详见 [Doc16](./Doc16_Unattended_Mode.md)

## 4. 业务主流程

### 4.1 程序启动 & 别名初始化

1. 双击 scToLocalDesk.exe，首次启动引导页
2. 用户设置本机唯一别名，本地 ini 持久化保存；检测内网别名冲突，冲突弹窗提示修改
3. 用户选择运行模式：【等待协助（被控）】 / 【远程协助（控制）】，运行时支持一键切换，无需重启

### 4.2 被控端流程

1. 被控模式：启动 Transport 服务（WebSocketServer）、启动 UDP 心跳上报
2. 收到客户端连接握手 → 向上抛出连接请求事件
3. QML 置顶弹窗（不可遮挡）：提示【IT【xxx】请求远程协助你的电脑】，按钮：同意 / 拒绝
   - 拒绝：直接关闭传输连接
   - 同意：正式建立会话，开始推送屏幕编码帧，接收键鼠指令、文件传输请求
4. 无人值守模式开启时，携带正确密码证明的连接走自动同意分支（挑战应答，不弹确认框，仅 Toast 提示 + 审计日志，见 Doc16）；密码错误走拒绝并计数
5. 会话期间悬浮常驻【一键断开】按钮，被控随时终止会话（无人值守会话同样可被人工随时切断）
6. 会话结束，关闭流，回到等待连接状态，持续心跳上报

### 4.3 控制端流程

1. 控制模式：输入目标设备别名，点击发起协助
2. AliasResolver 查找别名对应的 IP 与端口；找不到则友好提示：内网未找到该设备，请确认对方软件已打开
3. Transport 发起 ws 连接，等待被控确认；若对方开启了无人值守，可填入访问密码走自动同意通道
4. 被控同意后，打开远程画面窗口，键鼠透传生效；打开文件传输面板，支持拖拽双向传输文件

## 5. 功能需求

### 5.1 别名与设备发现

- 别名本地持久化；别名冲突检测告警
- IT 视图可见在线设备列表；员工小白视图隐藏设备列表
- 心跳周期、离线超时时间可配置（[Doc17](./Doc17_Settings_Page.md)）
- 支持静态别名映射（关闭组播发现，适合跨 VLAN 无法组播场景）

### 5.2 远程会话能力

- 屏幕采集、编码（MJPG/H264 可选），帧率、画质可调
- 鼠标移动、左右键、滚轮、键盘按键透传
- 远程窗口自适应缩放、全屏模式
- 网络闪断、对方退出、程序崩溃友好提示

### 5.3 文件传输

- 双向传输：控制端 ↔ 被控端
- 两种交互：文件树面板、拖拽文件进入远程窗口发起传输
- 文件分片传输、进度展示、失败重试
- 被控接收文件默认保存桌面，路径可自定义
- 文件传输二次确认弹窗（可全局开关）

### 5.4 托盘、自启、UI

- 最小化自动缩入系统托盘；托盘菜单：显示窗口、停止服务、退出程序
- 开机自启（注册表，Windows 适配器实现）
- QML 界面极简设计，大按钮、无专业术语，面向小白
- 单实例锁，同一台电脑仅允许一个 scToLocalDesk 运行

### 5.5 日志系统

- 等级：trace / debug / info / warn / error / critical
- 输出：滚动文件日志 + 控制台
- 结构化字段：session_id、device_alias、msg_type、error_code
- qDebug 重定向接入 spdlog，统一日志出口

### 5.6 无人值守模式（V1.1，设计见 Doc16）

- 被控端在设置页显式开启，默认关闭；开启时必须设置独立访问密码（与系统账户无关）
- 控制端连接时携带密码证明（挑战应答，密码不明文传输、不落盘），校验通过自动同意，无需被控端人工点确认
- 每次无人值守会话：Toast 轻提示 + 托盘徽标 + 审计日志（对方别名、时间、时长）
- 被控端会话内仍保留一键断开；密码错误拒绝并计数，为 V1.2 失败锁定预留
- 关闭开关仅影响新连接，不断开进行中的会话

### 5.7 设置页（设计见 Doc17）

- 页签：通用 / 网络与发现 / 会话与画质 / 文件传输 / 安全（含无人值守）/ 日志 / 关于
- 全量配置项持久化到 `config.ini`，key 契约以 Doc17 为准
- 员工视图隐藏高级页签（网络、发现、会话参数），仅展示别名、运行模式、文件保存路径
- 配置修改即时校验（端口占用、别名合法性），需重启生效的项明确标注

## 6. 安全需求

1. 新连接默认必须人工确认，不存在静默接管；唯一例外是用户显式开启的无人值守模式——独立密码 + 挑战应答鉴权通过后自动同意，且每次自动同意均产生可见提示与审计日志
2. 所有业务 Payload 载荷使用 AES-GCM 加密，传输链路加密
3. 仅内网可访问，不主动向外网发起连接
4. 会话生命周期强管理，连接断开自动释放采集、编码、传输资源
5. 无人值守密码只存 PBKDF2 哈希 + 随机盐，永不明文持久化、永不明文上网（见 Doc16 安全设计）

## 7. 非功能需求

1. Core 层（业务、协议、发现、会话、文件）禁止直接依赖 Qt 头文件；Qt 代码收敛在 platform/qt_adapter
2. 内存安全，资源 RAII 管理，裸指针最小化，优先 shared_ptr
3. 屏幕流做丢帧策略，只发送最新帧，避免发送队列堆积、内存暴涨
4. 普通用户权限可运行，屏幕捕获按需申请 Windows 录制权限
5. 组件可插拔：传输层、采集器、编码器、加密器、鉴权器、日志实现均可替换，不改动上层业务

## 8. V1 版本不实现清单

多显示器切换、会话录像、黑屏隐私保护、设备白名单、批量配置分发、失败次数锁定（V1.2）。

## 9. 风险清单

1. Windows 防火墙拦截 UDP 组播、WebSocket 监听端口：部署文档标注放行端口
2. WebSocket 发送速率过高队列堆积：业务层流量控制、丢帧策略
3. Windows 不同版本屏幕捕获 API 行为差异：采集器接口化，自动降级
4. 无人值守密码被暴力尝试：挑战应答 + 失败计数，V1.2 引入锁定与延迟应答；密码本身不明文传输、不可离线撞库（PBKDF2 高迭代成本）
5. 设置页写入非法值导致运行异常：ConfigParser 严格校验 + 默认值兜底（Doc17 校验规则）
