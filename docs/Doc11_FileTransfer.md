# Doc11 模块详细设计：双向文件传输子系统

> 版本：V2.0（2026-10-21 优化：补全分片字段表、状态机、重试与覆盖策略）

## 1. 接口与方向

- IFileTransfer 接口（Doc06 §5）；支持上传（控制 → 被控）、下载（被控 → 控制），协议层双向对等
- 复用会话通道（FILE_CHUNK，[Doc05 §5](./Doc05_Protocol.md)），V1 单会话内允许多文件排队、串行发送

## 2. 传输状态机（单文件）

```
Pending ──接收端确认（可配置弹窗）──▶ Transfering ──最后分片+校验──▶ Done
   │                                     │
   └─ reject / 取消 ──▶ Failed ◀── 断线/校验失败/磁盘错误
```

状态事件：`Evt_FileProgress`（file_id、已传字节、速率）、`Evt_FileDone`、`Evt_FileFailed`（原因码）。

## 3. 分片与完整性

| 机制 | 规则 |
| --- | --- |
| 分片大小 | 默认 256 KB（`file.chunk_size_kb`，64~1024 可配） |
| file_id | 16 B 随机，传输全程唯一标识 |
| 完整性校验 | total_chunks 计数 + 总大小对账；最后一片携带整文件 CRC32（V1），V1.2 升级 SHA256 |
| 重试 | 校验失败 / 中途断线：保留已收分片临时文件，重连后按 chunk_index 续传；V1 会话级重试（UI 手动），不跨会话 |

## 4. 接收端规则

1. 默认保存路径：桌面（`file.save_path` 可自定义，Doc17）
2. 同名文件：`file.overwrite` = ask（默认，弹窗询问）/ overwrite / rename（自动加 (1)）
3. 前置确认弹窗：`file.confirm_before_transfer=true` 时接收任何文件先弹窗（被控端建议常开）；关闭后仅 Toast 提示
4. 传输中可取消（cancel），半途文件删除临时文件
5. 磁盘空间预检：剩余空间 < 文件大小 → 直接 Failed 并提示

## 5. 交互入口

- 文件树面板（FileTransferPanel，Doc13）：浏览对端目录、上传 / 下载
- 拖拽：文件拖入远程画面窗口 → 自动发起发送（走前置确认开关）
- 进度：面板内进度条 + 速率 + 剩余时间；完成 / 失败列表可查看

## 6. 线程与性能

- 文件 IO、CRC 计算走全局线程池（Doc12），不阻塞编码 / 网络
- 顺序发送分片；发送队列复用 Transport 水位机制（FILE_CHUNK 不丢帧，见 Doc08 §4——与画面帧不同，文件分片不可丢）
- 大文件（>1 GB）实测目标：千兆内网 ≥ 40 MB/s，无内存增长

## 7. 测试要点

1. 小文件（1 KB）/ 大文件（4 GB）/ 中文名 / 特殊字符名
2. 传输中途拔网线 → 重连续传；取消 → 临时文件清理
3. 接收端磁盘满、只读目录 → Failed 原因码正确
4. 未鉴权会话注入 FILE_CHUNK：丢弃（安全用例，Doc09 §3）
